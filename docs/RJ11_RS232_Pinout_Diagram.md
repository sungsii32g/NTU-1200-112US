## 1. MOXA UPort 1110 深度可行性評估（可行嗎？有何風險？）

### 1.1 評估結論速覽
> [!CAUTION]
> **結論：強烈不建議使用 MOXA UPort 1110 作為本專案的光耦隔離介面！**
> 
> 原因在於：**MOXA UPort 1110「完全沒有」光耦電氣隔離 (No Galvanic / Opto-isolation)**，且在 Android 系統上存在 VID/PID 免驅動識別相容性障礙。

### 1.2 關鍵三大問題深度剖析

| 評估維度 | MOXA UPort 1110 現況 | 潛在致命風險 / 影響 |
| :--- | :--- | :--- |
| **① 光耦/電氣隔離** | **無光耦隔離**（僅有 15 kV ESD 靜電保護） | **高風險！** ESD 防護只防人體接觸放電，無法隔斷地迴路與高壓突波。NTU-1200 是 1200W 高功率逆變器，DC-AC 高頻 PWM 切換、感性負載開關或 UPS 市電旁路切換時，地電位跳動極大。非隔離轉接器的 USB-GND 與 DB9-GND 是直通的，突波可直接打入 Android 手機主機板與 CPU 造成燒毀！ |
| **② Android OTG 驅動** | 使用 MOXA 專屬 VID (`0x110A`) / PID (`0x1110`) | **相容性差！** Android 常用串口庫（如 `usb-serial-for-android` 及常見 Play 商店串口除錯 App）預設 Prober 僅認得 FTDI 原廠 VID (`0x0403`)、CH340 (`0x1A86`)、CP210x 等。插入手機時會提示「找不到可用裝置 / Device not recognized」，無法開箱即用。 |
| **③ 採購性價比** | 價格昂貴（原廠新品約 NT$1,800 ~ 2,500） | 花費昂貴卻**沒有買到光耦隔離保護**，失去工業防護的核心意義。 |

### 1.3 正確選型與推薦方案

1. **若非 MOXA 品牌不可**：
   - 請改選 **MOXA UPort 1150I**（注意型號結尾必須有 **`I`**，代表 **Isolation**）。
   - 具備 **2 kV 光耦電氣隔離**，支援 RS-232/422/485。
   - *注意：售價較高（約 NT$3,800 ~ 4,500），且 Android 端仍需使用自訂 ProbeTable 載入其驅動。*
2. **最佳推薦方案（性價比最高、相容性最好、真正光耦隔離）**：
   - 選用採用 **原生 FTDI (FT232RL) 或沁恆 (CH340) 晶片** 且標註 **「工業級光耦/磁耦電氣隔離 (1.5kV ~ 3kV)」** 的 USB 轉 RS-232 轉換器。
   - **代表品牌/型號**：
     - **微雪 (Waveshare) USB TO RS232 隔離版**（內建 ADuM 磁耦隔離 + 隔離電源）
     - **波士電子 (BOSI) USB-RS232-G 光耦隔離型**
     - **宇泰 (UTEK) UT-8801-I 工業級隔離型**
   - **優勢**：
     - 原生 FTDI/CH340 VID，Android 系統 (`usb-serial-for-android`) 100% 開箱即用、免改程式碼。
     - 具備實質光電/磁電隔離，手機與逆變器地電位完全切斷，徹底免疫突波干擾。
     - 市售價格約 NT$350 ~ 700，經濟實惠。

### 1.4 【手邊現有頂規升級】MOXA TCC-82 光電隔離器 (4 kV RMS 全模式通用 零元直接上線方案)

> [!TIP]
> **重要確認：MOXA TCC-82 具備「全模式通用特性」！**
> 只要不是直接選購一體成型的「微雪 Waveshare 工業級隔離 USB 轉 RS232/485」，其他任何非隔離轉接方案（如 **MOXA UPort 1110、UNITEK USB-RS232、MAX3232 模組**）在所有實作模式中**全部都能搭配 MOXA TCC-82** 獲得高達 4 kV 的實質光電隔離保護！

#### ① MOXA TCC-82 核心優勢與工作原理
* **隔離耐壓高達 4 kV RMS**：MOXA TCC-82 為工業級「埠供電型 RS-232 4通道光電隔離器 (Port-Powered RS-232 Isolator)」，提供 1 分鐘 4 kV RMS 高壓防護與 15 kV ESD 防護。
* **雙向信號全面光隔離**：隔離範圍涵蓋傳輸線 (**TxD, RxD**) 與交握線 (**RTS, CTS**)。
* **標準 DB9 母進公出**：一側為 DB9 母頭 (接收來自電腦/轉接器的 DB9 公頭)，另一側為 DB9 公頭 (輸出至 NTU-1200 特製線)。
* **埠供電免外接電源**：內部直接由 RS-232 信號線竊電運作，亦支援外接 5~12V 直流供電。
* **全模式通用性 (Universal Compatibility)**：
  - **模式一 (ESP32-S3)**：ESP32 UART2 ──► MAX3232 電平轉換板 (DB9公) ──► **MOXA TCC-82** ──► NTU-1200
  - **模式二 (Android 手機)**：手機 OTG ──► MOXA UPort 1110 或 UNITEK (DB9公) ──► **MOXA TCC-82** ──► NTU-1200
  - **模式三 (筆電 / 工控 PC)**：筆電 USB ──► MOXA UPort 1110 或 UNITEK (DB9公) ──► **MOXA TCC-82** ──► NTU-1200
  - **模式四 (RK3568 AIO-3568J)**：板載 RS-232 DB9 針腳 ──► **MOXA TCC-82** ──► NTU-1200

#### ③ MOXA TCC-82 雙側電源供電深度解析 (PC 端給多少？設備端給多少？還是都可以不用？)

許多工程人員在初次使用 MOXA TCC-82 時常有疑問：「這顆光電隔離器兩邊都有電源插孔，PC 端要給多少伏特？設備端 (NTU-1200) 又要給多少？還是其實兩邊都不用接？」

以下依據 MOXA 原廠硬體規範與 NTU-1200 實機量測結果，提供權威解答：

##### 1. 核心結論（一句話解答）：
> **「在標準情況下，PC 端與設備端都可以完全不用接外接電源（Port-Powered 埠供電）！但如果設備端 (NTU-1200) 因為只有 3 條線導致收不到訊號時，僅需在設備端補上 DC 5V~12V 獨立電源。」**

##### 2. TCC-82 內部雙側獨立供電原理
* **4 kV 實質光電隔離隔絕兩側**：TCC-82 的輸入側（PC 端）與輸出側（設備端）由 4 kV RMS 光耦元件及內部微型隔離障壁分開。
* **兩側電力 100% 獨立**：**兩側絕不能共用同一組未隔離的接地或電源線**，否則會破壞 4 kV 隔離障壁。
* **專利竊電迴路 (Port-Powered)**：TCC-82 內建電荷泵（Charge Pump）電源採集電路，只要序列埠的 **TxD、RTS、DTR** 任何一隻腳具備電壓（無論是正電壓 +12V 或負電壓 -12V），TCC-82 就會自動從信號線中竊取能量運作，功耗極低（僅約 20 mA @ 5V）。

##### 3. PC 端 (Side 1 / DB9 母孔)：【99% 完全不用接電源！】
* **連接硬體**：筆電/PC ──► MOXA UPort 1110 (或 UNITEK USB 轉 RS-232)。
* **為何不用接電源？**：
  - USB 轉 RS-232 轉換器具備完整 9-Pin 訊號線（TxD、RTS、DTR、CTS、DSR 等）。
  - 當上位機軟體（WPF 程式或 Web Serial）開啟通訊埠時，系統預設會拉起 RTS/DTR 訊號線（電壓通常為 +6V ~ +10V）。
  - UPort 1110 供電極為充沛，TCC-82 的 PC 側**保證能 100% 透過埠供電穩定工作，完全無須接外接電源**！
* **若真要外接時的規格**：DC **+5V ~ +12V**（可直接插筆電 USB 埠引出 5V 圓孔線供電）。

##### 4. 設備端 (Side 2 / DB9 公針，連向 NTU-1200)：【建議優先免接電源測試；若無回覆則補 DC 5V】
* **連接硬體**：TCC-82 DB9 公針 ──► 特製線 ──► NTU-1200 Remote Port (RJ11)。
* **關鍵技術細節**：
  - 明緯 NTU-1200 的 Remote Port (RJ11) 只有 3 條有效線（Pin 2 TxD、Pin 3 GND、Pin 4 RxD），**沒有 RTS 與 DTR 等硬體握手線**。
  - 不過，NTU-1200 內部的 RS-232 發送晶片在閒置待機時，TxD 腳位會維持在 RS-232 的標準 MARK 狀態（約 -6V 至 -10V 的負電壓）。
  - TCC-82 內部具備雙極性採集電路，**在大部分情況下，單靠 NTU-1200 TxD 的負電壓即可驅動設備端的光耦發射電路，因此設備端通常也無須外接電源**！
* **何時設備端才需要外接電源？**：
  - 若連線後上位機顯示發送 `Q\r`，但底部的「最後接收 (RX)」始終沒有收到 `(110.0 ...)` 遙測封包（逾時未回應）。
  - 這代表 NTU-1200 內部 RS-232 晶片的輸出驅動電流較弱，無法單線撐起 TCC-82 設備端的光耦電路。
* **設備端外接電源規格與【致命禁忌】**：
  - **電源規格**：DC **+5V ~ +12V**（電流需求僅 20 mA）。可以使用 TCC-82 盒內隨附的「USB 轉 DC Jack 圓孔供電線」或任何 5V 手機充電器。
  - ⚠️ **【極重要！致命禁忌——切勿短路隔離障壁】**：
    若設備端需要外接 5V 電源，**必須使用「插在牆上插座的獨立手機充電器」或「獨立行動電源」**！
    **絕對不能將設備端的 USB 供電線插回「同一台 PC/筆電的 USB 埠」！**
    **原因**：若將設備端的電源插回同一台 PC，PC 的 USB 負極 (GND) 就會與 NTU-1200 的通訊地線直接相連，這會將兩端的 4 kV 光耦隔離完全短路繞過，導致光電隔離保護當場失效！

##### 5. 快速判定速查表

| 連接側 | 訊號來源 | 推薦供電模式 | 外接電源規格 (若需要時) | 致命禁忌（千萬別做） |
| :--- | :--- | :--- | :--- | :--- |
| **PC 端 (Side 1)**<br>接 UPort 1110 / UNITEK | USB 轉 RS-232 DB9 | **【免接電源】(Port-Powered)**<br>UPort 1110 的 DTR/RTS/TxD 供電極為充足 | 若需外接：DC 5V~12V<br>(可插 PC 的 USB 埠取 5V) | 無特殊禁忌。 |
| **設備端 (Side 2)**<br>接 NTU-1200 RJ11 | NTU-1200 只有 TxD/RxD/GND 3線 | **【優先免接電源測試】**<br>若收不到逆變器回覆 `Q` 封包，則在設備端補供電 | 若需外接：**DC 5V~12V** (20mA)<br>可用手機 5V 充電頭獨立供電 | ⚠️ **嚴禁將設備端供電線插回同一台 PC 的 USB！**<br>否則會將兩側隔離 GND 短路，喪失 4 kV 防護。 |

## 2. 明緯原廠規格書核定：RJ11 (6P4C) 介面與定義


> **明緯原廠規格核定**：沒記錯！明緯 NTU-1200 原廠規格書與通訊手冊明確記載機身 Remote Port 為 **`RJ11 (6P4C)`** 規格，明緯原廠選購通訊線材料號為 **`RJ11-RS232`** (或 **`DS-RJ11-RS232`**)。

### 2.1 6P4C vs 6P6C vs 6P2C 規格明確辨識

```
【RJ11 規格剖析 (水晶頭正面俯視圖)】

  6P4C (原廠標準規格，推薦)：
  ┌───┬───┬───┬───┬───┬───┐
  │ 1 │ 2 │ 3 │ 4 │ 5 │ 6 │  外殼共有 6 個插槽位置 (6 Positions)
  │ 空│ 金│ 金│ 金│ 金│ 空│  僅中間 4 槽安裝鍍金彈片 (4 Contacts: Pin 2, 3, 4, 5)
  └───┴───┴───┴───┴───┴───┘  最外側 Pin 1 與 Pin 6 為塑膠空槽

  6P6C (手邊有此規格亦可代用)：
  ┌───┬───┬───┬───┬───┬───┐
  │ 1 │ 2 │ 3 │ 4 │ 5 │ 6 │  6 槽皆有金屬彈片。製作特製線時只需壓接 Pin 2, 3, 4，
  │ 金│ 金│ 金│ 金│ 金│ 金│  Pin 1, 5, 6 懸空 (NC) 不接線即可。
  └───┴───┴───┴───┴───┴───┘

  6P2C (⚠️ 絕對不可使用！)：
  ┌───┬───┬───┬───┬───┬───┐
  │ 1 │ 2 │ 3 │ 4 │ 5 │ 6 │  常見於最便宜的電話單音線，僅中間 2 槽有金屬片。
  │ 空│ 空│ 金│ 金│ 空│ 空│  缺少 Pin 2 或 Pin 4，無法進行雙向數據傳輸！
  └───┴───┴───┴───┴───┴───┘
```

## 3. DB9 Pin - RJ11 (6P4C) 特製品接線架構圖（保證 100% 正確指南）

自製線材（特製品）需要對接 USB-RS232 轉換器。
市售 USB 轉 RS-232 模組端均為 **DB9 公頭 (Male, 帶針腳)**，因此自製線的 DB9 端必須使用 **DB9 母頭 (Female, 帶 9 孔)** 插座。

### 3.1 訊號名稱與流向對照總表 (標準 Null-Modem 交叉連線)

| 訊號意義 | MEAN WELL NTU-1200 遠端埠 (RJ11 6P4C) | 標準 RS-232 (DB9 母頭孔位) | 物理訊號流向說明 |
| :--- | :---: | :---: | :--- |
| **主機發送指令 ──► 逆變器接收** | **Pin 2 (Rx)** | **Pin 3 (TXD)** | 手機/主控發出 ASCII 指令 ──► 進入 NTU RJ11 Pin 2 |
| **信號參考地** | **Pin 3 (GND)** | **Pin 5 (GND)** | 雙端共用通訊地電位（經光耦與手機端完全隔離） |
| **逆變器回傳數據 ──► 主機接收** | **Pin 4 (Tx)** | **Pin 2 (RXD)** | NTU 回傳遙測狀態字串 ──► 進入手機/主控接收 Pin 2 |
| *(未連接 / 懸空)* | Pin 1, 5, 6 (NC) | Pin 1, 4, 6, 7, 8, 9 (NC) | 嚴禁接線，直接懸空剪斷或包覆絕緣 |

### 3.4 四芯電話線「剪線剝皮直鎖」實務指引 (淘寶套件最佳裝配法)

> [!WARNING]
> **常見致命陷阱提醒**：
> 市售「USB 轉 RS232/485 隔離轉換器 (FT232RNL 晶片)」機身上的**綠色螺絲接線端子是給 RS-485 用的 (A+, B-, GND)**！
> 明緯 NTU-1200 是 **RS-232 電平（±5V ~ ±12V）**，轉換器上的 RS-232 介面為 **DB9 公頭 (9 根凸起公針)**。
> ⚠️ **裸銅線無法直接夾入 DB9 公針！千萬不可誤夾入綠色的 RS-485 端子，否則通訊不通甚至可能燒毀通訊晶片！**

#### ✅ 必備橋樑：加購「DB9 母頭 免焊接接線端子 (帶外殼)」
只需加購一個 **DB9 母頭免焊接端子**（淘寶約 3~8 元人民幣），即可實現「剪線剝皮、免烙鐵螺絲直鎖」：

```
【實體連接拓撲】
[手機 OTG] ──► [FT232RNL 隔離轉換器] ──► (DB9 公頭 9 針)
                                              │
                      ┌───────────────────────┘ (插上)
                      ▼
             ┌─────────────────────────┐
             │ DB9 母頭 免焊接接線端子  │
             │ (背面帶 9 個螺絲壓線孔)  │
             └────────┬───┬───┬────────┘
                      │   │   │
             Pin 3(TX)│   │   │Pin 2(RX)
                      │   │Pin 5(GND)
                      ▼   ▼   ▼
              [3 根剝開之電話線芯直接鎖入]
                      │
           (長約 1~2 米之四芯電話線)
                      │
                      ▼
         [RJ11 6P4C 水晶頭 (未剪)] ──► 插入 NTU-1200 Remote Port
```

### 3.5 四芯扁平電話線常用顏色對應表 (美標標準)

若使用市面最常見的四芯扁平電話排線壓接，請依下表順序比對線色：

| RJ11 槽位 | 6P4C 壓接線色 | 訊號功能 | 對應連接至 DB9 母頭孔位 | 備註 |
| :---: | :---: | :---: | :---: | :--- |
| **Pin 1** | *(無)* | NC 空腳 | — | 6P4C 該槽無金屬片 |
| **Pin 2** | **黑 (Black)** | **Rx** | **DB9 Pin 3 (TXD)** | 指令傳入逆變器 |
| **Pin 3** | **紅 (Red)** | **GND** | **DB9 Pin 5 (GND)** | 隔離通訊參考地 |
| **Pin 4** | **綠 (Green)** | **Tx** | **DB9 Pin 2 (RXD)** | 逆變器遙測字串送出 |
| **Pin 5** | **黃 (Yellow)** | NC 空腳 | — | 剪斷或絕緣，不接 DB9 |
| **Pin 6** | *(無)* | NC 空腳 | — | 6P4C 該槽無金屬片 |

> **⚠️ 注意事項 (重要)**：不同批次電話線工廠內部線色排序可能不同。**絕不可盲信顏色！**
> 最保險的做法：拿起未剪的 RJ11 水晶頭，將銅片朝上朝向自己、卡榫朝下，由左至右看進去：
> - 數到第 2 個金屬槽位的線色 ──► 鎖入 DB9 母端子的 **Pin 3**。
> - 數到第 3 個金屬槽位的線色 ──► 鎖入 DB9 母端子的 **Pin 5**。
> - 數到第 4 個金屬槽位的線色 ──► 鎖入 DB9 母端子的 **Pin 2**。
> - 第 5 個金屬槽位的線色 ──► **直接剪平，不可鎖入任何孔**！

### 3.6 特製品上電前「零失誤三步電錶驗收法」

製作完成後，**請務必在通電連接前依序完成以下 3 個步驟測試**，以確保 100% 正確：

```
步驟 1：導通檢查 (三用電表切換至蜂鳴檔)
  - 紅黑表筆分別點測：【DB9 Pin 3】與【RJ11 Pin 2】 ──► 必須響鳴嗶聲 (導通，電阻 < 1Ω)
  - 紅黑表筆分別點測：【DB9 Pin 5】與【RJ11 Pin 3】 ──► 必須響鳴嗶聲 (導通，電阻 < 1Ω)
  - 紅黑表筆分別點測：【DB9 Pin 2】與【RJ11 Pin 4】 ──► 必須響鳴嗶聲 (導通，電阻 < 1Ω)

步驟 2：防短路絕緣檢查 (三用電表歐姆檔 200kΩ / 2MΩ)
  - 量測 DB9 母頭 Pin 2、Pin 3、Pin 5 彼此之間：
    - Pin 2 與 Pin 3 之間 ──► 必須為無限大斷路 (OL / 1)
    - Pin 2 與 Pin 5 之間 ──► 必須為無限大斷路 (OL / 1)
    - Pin 3 與 Pin 5 之間 ──► 必須為無限大斷路 (OL / 1)
  *(若有任何阻值，表示水晶頭壓偏短路或 DB9 端子毛邊搭鐵，絕不可上電！)*

步驟 3：空載直流電壓驗證 (上電防呆)
  - 將製作好的 RJ11 水晶頭插上 NTU-1200 逆變器，逆變器開啟電源開關。
  - 特製線 DB9 母頭端暫時「不要」接 USB 轉接器，保持懸空。
  - 三用電表切至直流電壓檔 (DC 20V)：
    - 黑表筆接 【DB9 Pin 5 (GND)】
    - 紅表筆測 【DB9 Pin 2 (來自 Inverter Tx)】 ──► 應量測到 -5.0V 至 -10.0V 之間的負電壓！
      (標準 EIA/TIA-232 待機空閒狀態為邏輯 1，對地為負電壓；若量到負電壓，證明 Tx 與 GND 腳位 100% 正確！)
    - 紅表筆測 【DB9 Pin 3 (來自 Inverter Rx)】 ──► 應量測到約 0.0V (逆變器高阻抗輸入端)。
```

## 5. 小型 USB 轉 TTL 轉接板 (FT232BL / CP2104 3.3V) 開發定位與防呆指南

手邊現有的兩款小型 USB-TTL 模組：
1. **FT232BL 轉接板** (3.3V / 5V TTL)
2. **CP2104 轉接板** (3.3V TTL，原搭配 RK3568 除錯使用)

### 5.1 正確用途 (安全開發情境)
* **情境 1：PC 與手機 / 模擬器 閉環回環測試 (Loopback / Mock Inverter)**：
  - 手機 OTG 連接 FT232BL，PC 端連接 CP2104。
  - 將兩者的 `TXD` 交叉對接 `RXD`，`GND` 共地。
  - PC 端執行 Python Mock 腳本模擬 NTU-1200 逆變器回應，手機 App 進行完整通訊調試。
* **情境 2：邏輯分析儀指令波形抓取**：
  - 夾取 FT232BL 的 TXD 與 GND，驗證 Android App 發送的 `Q\r`、`C 1\r` 是否精確合規。
* **情境 3：RK3568 開發板系統 Console 除錯**：
  - CP2104 接入 AIO-3568J 的 Debug UART (波特率通常為 1500000)，用於抓取 Linux Kernel Boot Log。

> [!CAUTION]
> **嚴正安全防呆警示 (絕對不可違反)**：
> * **嚴禁將 FT232BL 或 CP2104 的 TTL 針腳直接插入 NTU-1200 的 RJ11 埠！**
> * FT232BL / CP2104 的信號電平為 **0~3.3V (TTL)**；而 NTU-1200 為 **±5V~±12V (EIA RS-232 負電壓)**。
> * 直接插上將導致逆變器的負高壓倒灌，瞬間燒毀 3.3V TTL 晶片！
> * 實機連線請務必遵守：**必須透過標準 RS-232 收發器 + 電氣隔離 (如 MOXA TCC-82 或微雪隔離版)**。
